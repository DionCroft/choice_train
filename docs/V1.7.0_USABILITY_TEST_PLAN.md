# V1.7.0-alpha School Usability Test Plan

**Status update, 7 November 2026:** the candidate passed the automated engineering gate and was promoted as stable V1.7.0. This plan remains active for physical-device, practitioner, learner, privacy, and school deployment validation.

## Purpose

This plan evaluates whether the V1.7.0 interface is suitable for school use after engineering promotion. It does not test clinical efficacy. Use synthetic pupil data until the school's data-protection, consent, safeguarding, and retention arrangements are confirmed.

## Participants and Setting

- at least three teachers or TAs with different levels of ChoiceTrain familiarity
- the school's SEND/accessibility lead
- a small, appropriately consented learner group selected by the school
- one researcher or administrator for export and EEG workflow review
- representative Windows touchscreen, iPad Safari, Android Chrome, and any intended Kindle Silk device

Record device, browser, input method, pupil alias, presentation preferences, task, interruptions, and support given. Do not put identifiable pupil data in GitHub issues or test evidence.

## Teacher Tasks

1. Open the alpha and identify that it is not the live release.
2. Select or create a synthetic pupil.
3. Confirm current level, task, question count, and session length.
4. Change font, text size, motion, feedback sound, and celebration.
5. Add a context note and personalised image.
6. Start learner mode using the primary action.
7. Return using the deliberate hold control.
8. Find basic results and export a session.
9. Open Admin Overview, Sessions, Learners, EEG, and System; confirm each destination shows relevant content without searching one long page.
10. Explain what Reset changes and what remains stored.

Measure completion, time, wrong turns, questions asked, accidental starts/exits, and confidence on a 1-5 scale. A task fails if a participant needs developer intervention.

## Learner Observation

Use the least intrusive settings first and adapt rather than forcing a standard configuration. Observe:

- whether the prompt and target are noticed
- target selection and accidental touches
- requests for help, break, stop, repeat, or sound change
- response to motion, sound, reward, and screen brightness
- whether the reward interrupts or supports re-engagement
- accidental activation of the teacher return
- signs of fatigue, distress, avoidance, or sensory discomfort
- preferred font, text scale, theme, sound, motion, and celebration
- whether correct, incorrect, current, selected, and warning states remain understandable without relying on colour alone

Stop or adapt immediately under the school's normal safeguarding and regulation practice. Do not infer a diagnosis from a preference or response.

## Admin and Research Tasks

1. Locate a stored session.
2. Review learner history and attention-family outputs.
3. Export ordinary session JSON, EEG/research data, and stored history.
4. Verify build version, schema, pupil alias, exact prompts, context notes, presentation preferences, support, trials, and marker arrays.
5. Confirm that no raw image bytes are included in an ordinary session export.
6. Confirm that audio and reward events use codes 32 and 33.
7. Confirm that browser markers are described as exploratory and not hardware-synchronised.

## Automated and Technical Checks

- stable and alpha Playwright suites pass together
- JavaScript syntax check passes
- duplicate HTML IDs are absent
- teacher/admin text contrast is at least 4.5:1, with the main panel target of 7:1
- primary classroom controls meet or exceed 44 CSS pixels where layout permits
- learner mode has no unintended vertical page scroll at tested tablet/mobile viewports
- Help, Break, Stop, prompt, and progress remain visible and operable at a 390-pixel mobile viewport
- keyboard focus is visible and workspace navigation is operable
- system and selected reduced-motion modes suppress non-essential animation
- TTS-disabled and SpeechSynthesis-unavailable paths remain usable
- feedback audio does not overlap active speech
- no runtime request leaves the application origin
- theme and sensory preferences survive reload and pupil switching
- every theme controls learner DOM components and runtime-drawn cues/charts consistently
- exports follow the school-friendly filename and contain required fields

Run the complete local matrix with `npm run test:browser`. Run `npm run audit:visual:v170` to regenerate the 17-view synthetic-data review set for staff workspaces, learner states, responsive sizes, and every theme. Generated evidence stays under ignored `test-results/`; do not use real pupil data.

Current technical baseline: 77 Playwright checks pass locally, comprising 56 stable/archive regressions and 21 alpha-specific checks. This is an engineering baseline, not evidence that a colour, font, sound, or reward setting is suitable for an individual learner.

## Acceptance Criteria

- all automated regression tests pass with no uncaught browser errors
- every staff participant completes the daily session route without developer help
- at least 80% of staff tasks complete on the first attempt
- no critical accessibility, privacy, data-loss, broken-task, or learner-trap defect remains
- learner return cannot be triggered by an ordinary tap
- every sensory/reward feature can be reduced or disabled
- no participant interprets the tool as diagnostic based on interface wording
- school staff accept the data flow and export process
- the research team accepts marker definitions and documented timing limits
- explicit product-owner approval is recorded before `index.html` changes

## Issue Severity

- **Blocker:** data loss, external disclosure, inaccessible learner escape, broken task logic, incorrect target, invalid research event, or stable regression
- **High:** teacher cannot start/export, admin destination unavailable, severe device layout problem, preference does not persist
- **Medium:** confusing wording, avoidable navigation detour, inconsistent visual state, non-critical audio/motion issue
- **Low:** polish, spacing, copy refinement, or optional enhancement

## Promotion Record

Record test date, commit, devices, participants by role, synthetic/real-data status, failures, accepted limitations, and approval. Do not promote by copying files manually without a passing commit-specific test record and build stamp.
