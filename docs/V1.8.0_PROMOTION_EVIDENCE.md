# V1.8.0 Promotion Evidence Record

This record converts the human and external release gates into an auditable, fail-closed checklist. It does not approve V1.8 and must not contain pupil information.

The current machine-readable record is [`V1.8.0_PROMOTION_EVIDENCE.json`](V1.8.0_PROMOTION_EVIDENCE.json). Every gate is deliberately `pending` while V1.8 remains experimental.

The separate [`V1.8.0_IMPLEMENTATION_COVERAGE.json`](V1.8.0_IMPLEMENTATION_COVERAGE.json) record checks that declared internal capabilities still have repository evidence. It cannot populate this promotion record, freeze a commit, or approve a human or external gate.

Use the pupil-data-free [`V1.8.0_EXTERNAL_VALIDATION_PROTOCOL.md`](V1.8.0_EXTERNAL_VALIDATION_PROTOCOL.md) to run the staff, safeguarding, governance, physical-device, assistive-access, and EEG timing reviews. Store protected source records outside the repository and enter only their non-identifying references here.

`npm run build:review-pack:v180` can create an ignored pupil-data-free engineering hand-off and blank external-validation worksheet for the exact commit. The worksheet standardises staff, physical-device, access, safeguarding, governance, ethics, and EEG timing records, but must be completed and stored only in the approved external evidence location. These files are reviewer aids, not evidence that a gate passed, a candidate-freeze record, or promotion approval.

## Evidence Rules

- Freeze the reviewed candidate first, then set `candidate_commit` to its full 40-character Git commit SHA.
- Use `passed` only when the named review was completed against that frozen commit.
- Use `passed-with-limitations` only when the limitation is explicit, accepted by the responsible reviewer, and recorded in `limitations`.
- Record a non-identifying role or review group in `reviewed_by`, a `YYYY-MM-DD` date, and an evidence reference.
- Evidence references may be a public CI URL or an internal school, governance, ethics, usability, device-test, or laboratory record identifier.
- Do not commit pupil names, aliases, photographs, session exports, consent forms, safeguarding records, EEG recordings, free-text pupil observations, or other personal data. Keep protected evidence in the approved external record system.
- Set `promotion_authorised` to `true` only after the product owner has explicitly approved promotion and every required gate has acceptable evidence.

## Required Gates

| Gate | Evidence expected |
|---|---|
| Automated engineering | Exact-command results for release, schema, candidate, syntax, and complete browser gates on the frozen commit |
| Branch CI | Successful GitHub Actions run for the frozen commit |
| Product-owner approval | Explicit approval reference for V1.8 promotion |
| Staff usability | Teacher/TA workflow review using representative classroom tasks |
| Learner safeguarding | Safeguarding, assent/authority, and learner-observation process review |
| Information governance | School privacy, retention, access, export, and DPIA/governance decision |
| Legal/ethics | Applicable legal and research-ethics approval or documented decision |
| Windows touchscreen | Physical-device and touch-access record |
| iPad Safari | Physical-device and browser record |
| Android Chrome | Physical-device and browser record |
| Kindle Silk | Intended Kindle physical-device and browser record |
| Assistive access | Relevant keyboard, switch, AAC, or other intended access-method review |
| EEG hardware timing | Acquisition-system integration plus measured end-to-end marker latency and limitations |

## Commands

Validate that the committed record has the complete safe structure without making a promotion decision:

```bash
node scripts/check-v180-promotion.js --structure-check
```

After evidence has been recorded against the frozen candidate, run the fail-closed promotion check:

```bash
npm run check:promotion:v180
```

The second command is expected to fail while any gate is pending, failed, missing evidence, attached to a different commit, or marked `passed-with-limitations` without an explicit limitation. A successful result is necessary but not sufficient for promotion: the release procedure and final human confirmation still apply.
