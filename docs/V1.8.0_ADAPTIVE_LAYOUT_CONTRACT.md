# V1.8.0 Adaptive Layout Contract

## Purpose

ChoiceTrain is browser first and must adapt to the usable browser area rather than assume one device, resolution, orientation, pixel density, or input method. This contract defines the engineering behavior for the isolated V1.8 candidate. It does not replace testing on the school's physical devices or with the intended learner access methods.

## Layout Ranges

| Usable CSS-pixel range | Primary layout behavior |
|---|---|
| 320-479 px wide | Compact staff navigation, a setup-only Teacher workspace until learner preview is explicitly opened, two-column learner choices where appropriate, internally scrolling research tables, visible 44 px or larger learner controls |
| 480-900 px wide | Single-column setup-only staff workspace, flexible full-viewport learner grid after Start/Preview, tablet and split-screen containment |
| 901-1100 px wide | Teacher panel plus learner preview with a reduced but usable stage |
| Above 1100 px | Teacher panel plus flexible stage; Admin and Research content remains centred and width bounded |
| Landscape at 540 px high or less | Prompt and choices use a side-by-side learner composition with reduced non-essential chrome |
| Landscape at 360 px high or less | Student-friendly mode further reduces labels while retaining the prompt, choices, Help, Break, Stop, and deliberate teacher return |

These are layout ranges, not device detection. A phone at browser zoom, a tablet in split screen, a laptop with enlarged text, or a foldable can enter the same range.

## Usable Viewport

- CSS uses `vh` as a legacy fallback and `dvh` where supported.
- JavaScript mirrors `window.visualViewport` height and width into CSS variables when available.
- Learner mode uses the current usable height so mobile browser chrome, orientation changes, and on-screen keyboard changes do not leave controls below the visible area.
- Relayout of an active question preserves the question, response timer, trial number, and research-marker count.
- Safe-area insets protect controls on notched and rounded displays.

## Staff Workspaces

- Teacher and Admin navigation remains reachable without page-level horizontal scrolling at 320 CSS pixels and 130% in-app text.
- At 900 CSS pixels or less, the Teacher workspace does not place a second learner canvas below the setup form. `Start learner session` and `Preview learner view` open the activity in the full usable viewport; this prevents a long duplicated page on phones, portrait tablets, split-screen windows, and enlarged browser zoom.
- Mobile form controls use a scalable 1rem font size to avoid unintended iOS focus zoom while retaining browser zoom and user text scaling.
- Wide Research tables scroll inside their labelled card. Research cards and canvases remain within the page width.
- The photo editor is constrained to the usable viewport and scrolls internally.
- Coarse-pointer controls receive larger touch targets without changing keyboard behavior.

## Learner Workspace

- The prompt, all configured answer options, progress, and learner controls must fit in the usable viewport for the tested route.
- Answer count may change grid composition but must not place a choice outside the play area.
- Learner controls retain at least 44 CSS pixels of height.
- Presentation may become more compact, but the target rule and scoring must not change because of viewport size.
- Student-friendly mode may remove secondary technical text, never the primary prompt, answer choices, or Help/Break/Stop controls.
- Long personalised prompts and labels wrap inside their cards. If content still exceeds an extreme usable height, the active screen scrolls internally instead of clipping the prompt or an answer.

## Automated Matrix

The branch tests cover:

- 320 x 568 phone portrait at 130% text with six choices
- 360 x 480 short-phone portrait at 130% text with six choices
- 568 x 320 phone landscape at 130% text with six choices
- 844 x 390 compact landscape at 130% text with six choices
- 390 x 844 representative phone, 600 x 960 Kindle-shaped tablet, and 1366 x 768 short laptop
- live portrait-to-landscape relayout without question or marker restart
- 320 x 568 Teacher/Admin and Research reflow
- 390 x 844 Teacher setup-only routing followed by an explicit full-viewport learner preview
- 360 x 640 photo-editor containment
- Android-like Chromium, iPad-like WebKit, and Kindle Silk-shaped Chromium compatibility routes

## Research Delivery Context

- New sessions freeze delivery-context contract `1.0.0` at learner-session start and end.
- The record contains usable browser-area dimensions in CSS pixels, a width band, orientation, pointer capability, reported touch capability, fullscreen state, and input types actually observed in the activity.
- The record excludes user-agent strings, platform identifiers, device identifiers, and device-pixel ratio.
- Research summary `2.3.0` visualises this context so display or access changes can be reviewed alongside outcomes. It is a delivery covariate, not a learner trait, ability score, explanation of performance, or substitute for physical-device validation.

## External Validation Still Required

Automated emulation cannot approve physical-device suitability. Before promotion, test the frozen candidate on the intended Windows touchscreen, iPad Safari, Android Chrome, and Kindle Silk hardware, including portrait and landscape, browser zoom or text size, on-screen keyboard, speech, touch, school restrictions, and intended assistive access. Record results through the external validation protocol without committing pupil data.
